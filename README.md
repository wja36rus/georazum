# Гео Разум

SaaS-сервис формирования **аналитического заключения по земельному участку**
по кадастровому номеру (можно несколько участков в одном заказе). Пользователь
выбирает уровень анализа (S / M / L), заполняет анкету, оплачивает картой,
сервис асинхронно собирает отчёт и выдаёт его для печати/PDF.

ТЗ: [`ГР ТЗ сайт.docx`](ГР%20ТЗ%20сайт.docx)

## Стек

| Часть        | Технологии                                                                                                                                  |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Backend      | Node.js + Express (чистый JS), in-memory БД, scrypt-пароли, мок-генерация отчётов                                                           |
| Frontend     | React 19 + TypeScript (strict) + **Rspack**, FSD, SCSS (дизайн-токены), SVG-иконки как React-компоненты, react-router-dom v7, Vitest (unit) |
| Сборка/тесты | `@rspack/cli` + swc-loader · типчек `tsc --noEmit` · Vitest + jsdom                                                                         |

Дизайн — по референсу дашборда, основные цвета **голубой и зелёный**
(палитра в [`context/design.md`](context/design.md)).

## Запуск

Требуется Node.js 18+ (проверено на Node 24). Два терминала:

**Терминал 1 — API:**

```sh
cd server
npm install
npm start          # http://127.0.0.1:4000
```

**Терминал 2 — клиент:**

```sh
cd client
npm install
npm run dev        # http://127.0.0.1:5173 (прокси /api → 4000)
```

Откройте http://127.0.0.1:5173.

## Демо-доступы

| Роль          | Логин               | Пароль     |
| ------------- | ------------------- | ---------- |
| Пользователь  | `ivan@mail.ru`      | `demo1234` |
| Администратор | `admin@georazum.ru` | `admin123` |

### Что можно проверить руками

- **Сценарий заказа**: войти как Иван → «Новый анализ» → ввести кадастровый
  номер `36:16:3405742:189` (уровень S), `36:34:1823050:441` (M) или
  `36:25:6945030:776` (L) — можно добавить несколько участков
  (`36:16:3405742:190`/`…191` смежны с `…189`: покажется суммарная площадь и
  проверка взаимного расположения) → уровень → анкета параметров (M: 6 блоков,
  L: 7 блоков) → тип заказчика (физлицо / ИП / юрлицо) → контакты и согласия →
  единый экран проверки заказа → оплата картой
  `4111 1111 1111 1111`, срок `12/30`, CVV `123`, holder `IVAN IVANOV` →
  статус генерации (поллинг) → отчёт → «Скачать PDF» (печать).
- **Карта-отказ**: `0000 0000 0000 0000` → «Платёж отклонён банком» (HTTP 402).
- **Админка**: `/admin` — статистика, заказы (смена статуса), пользователи
  (блокировка), тарифы, генерации, редактирование оферты.
- **ЛК**: `/cabinet` — табы: обзор, заказы, отчёты, платежи, документы,
  профиль, поддержка.

## Что замокано (осознанный предел прототипа)

- База данных — in-memory (`server/src/db.js`): **рестарт сервера сбрасывает
  все данные**, включая незавершённые генерации.
- Платёжный шлюз, email-письма, кадастровый реестр и сама генерация отчёта —
  заглушки. Отчёт собирается по шаблону `buildReport` (уровни S/M/L).
- Подтверждение email — мок: аккаунт подтверждается автоматически.
- Многоучастковые заказы, проверка взаимного расположения и данные заказчика
  (`order.customer`) — реализованы только в клиентских моках
  (`client/src/shared/api/mock/`); реальный сервер принимает один `cadastral`.
- Прод-замена: PostgreSQL + Redis, JWT, BullMQ, реальный платёжный провайдер,
  кадастровые источники, SMTP.

## Деплой

GitHub Pages отдаёт только статику, поэтому бэкенд разворачивается отдельно
(бесплатно: Render / Railway / Fly.io). Схема:

```
https://<user>.github.io/georazum/  (React — GitHub Pages)
        └── fetch → https://<api-host>/api/...  (Express — Render/Railway)
```

### 1. Бэкенд (Render и т.п.)

- Создать Web Service из репозитория, root directory `server`,
  build: `npm install`, start: `npm start`.
- Render сам задаёт `PORT` (код читает `process.env.PORT`). CORS уже включён
  (`app.use(cors())`).
- ВАЖНО: БД in-memory — данные сбрасываются при рестарте/сне бесплатного
  хоста. Для демо нормально.

### 1а. Демо без бэкенда (режим моков)

Сайт на статике работает **и без развёрнутого API**: продакшен-сборка без
`API_URL` автоматически включает мок-режим (`USE_MOCKS`) — все данные
(уровни, участки, пользователи, заказы, отчёты) живут в памяти браузера,
нужен только GitHub Pages. Работает логин/регистрация, заказы, оплата
(карта-отказ `0000…` → 402), генерация, ЛК и админка. Как только зададите
`API_URL` — сайт автоматически переключится на реальный бэкенд
(флаг `USE_MOCKS` при необходимости: `client/src/shared/api/mock/`).

### 2. Фронтенд (GitHub Pages)

- В настройках репозитория: Settings → Pages → Source: **GitHub Actions**.
- В репозитории задать переменную `API_URL` (Settings → Secrets and
  variables → Actions → Variables): адрес развёрнутого API, например
  `https://georazum-api.onrender.com` (без `/api` — префикс добавляет клиент).
- Workflow `.github/workflows/deploy-pages.yml` соберёт клиент
  (`BASE_PATH=/georazum/`, `API_URL` из переменной) и задеплоит на Pages при
  пуше в `main` (или вручную через Actions → Deploy client → Run workflow).
- SPA-роуты работают благодаря `404.html` = копии `index.html`.
- `<BrowserRouter basename>` берётся из `BASE_PATH` (встраивается DefinePlugin):
  на Pages `BASE_PATH=/georazum/` → все маршруты и переходы — строго под
  `/georazum/`, перезагрузка любой страницы работает, без 404.

Локальная разработка не меняется: без env-переменных `BASE_PATH=/` и
`API_URL=""` (тот же origin, прокси `/api` → 4000).

### Локальные сборки через `.env`

Клиент читает `client/.env` (через dotenv в `rspack.config.ts`):

```
# client/.env (в git не коммитится; пример — client/.env.example)
API_URL=https://georazum-api.onrender.com   # пусто = моки в prod-сборке / dev-прокси
BASE_PATH=/georazum/                        # для деплоя в подпапку Pages
USE_MOCKS=                                  # (опц.) true/false — принудительно
```

Уже заданные системные переменные окружения имеют приоритет над `.env`.
Для CI переменные задаются в GitHub Actions (`vars.API_URL` в workflow).
